Byte-extent aliasing

In COBOL, memory is bytes, not variables. Treat every field as a byte range and aliasing follows from one test: do two ranges overlap?

The problem

The reaching definitions page tracked writes by variable name. That works when every name owns its own storage. In COBOL many names share storage. A group like REC is just the bytes of its children laid end to end, so writing REC writes WS-A and WS-B. REDEFINES gives the same bytes a second name with a different shape. A move into one child changes half of the group. Tracking by name gets every one of these wrong.

The intuition

Lay the program's data out as the compiler does: each field is a start offset and a length in some storage region. Forget names. A write paints the bytes it covers. A read looks at the bytes it covers and asks which writes painted any of them. Two fields alias when their ranges overlap — whatever they are called, however they were declared.

The example

REC is eight bytes: WS-A is bytes 0–4 and WS-B is bytes 4–8. WHOLE redefines the same eight bytes as one field. The program writes the group, then one child, then reads each child and the redefinition.

The rule

extent = (region, start, end)
may_alias(a, b) = same region ∧ a.start < b.end ∧ b.start < a.end
must_cover(w, d) = same region ∧ w.start ≤ d.start ∧ d.end ≤ w.end ∧ w is exact
kill(s) = { d | s's write must_cover d }
definers(read r at s) = { d ∈ in(s) | may_alias(d, r) }

Two different tests, on purpose. A definition is a possible source of a read when it overlaps any byte of it. A definition is certainly gone only when a later write covers every byte it wrote. Anything between — a partial overwrite — leaves it alive.

What goes wrong

  • The answer can be loose. At MAIN-PARA/2 the strip shows that bytes 0–4 were last written by MAIN-PARA/1 alone. But the analysis keeps one definition per write, and MAIN-PARA/1 covers only half of MAIN-PARA/0's eight bytes, so it cannot kill it. MAIN-PARA/0 still overlaps the read, and is reported as a definer although none of its bytes survive there. That is an over-approximation: it never misses a real source, it sometimes names one too many. Getting it exact would mean splitting a definition into byte ranges every time something writes part of it.
  • Kill only on certainty. A write whose position is not known exactly — a table element with a computed subscript, a field after an OCCURS DEPENDING ON — may alias widely but must cover nothing. Treating it as covering would delete real sources: a wrong answer, not a loose one.
  • A field that cannot be sized has no extent at all, and the analysis cannot place its reads and writes. Cobble reports such a program as unsizeable rather than guess.

In cobble

Every field's extent comes from its declaration alone — level, usage, OCCURS, REDEFINES — in extent.py. The two tests are may_alias and must_cover on the extent type in red-dragon's field_extent.py. A move of a literal has no source field, so cobble names its source LITERAL.
