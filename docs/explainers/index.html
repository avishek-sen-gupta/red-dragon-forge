cobble · field dataflow

Algorithm explainers

The techniques cobble's field dataflow is built on, for engineers who have not met them before. Each page states a problem, walks a small COBOL program one statement at a time with the analysis state after each, and ends with the precise rule and where it goes wrong.

Read them in order; each builds on the one before.

  1. Visiting a graph: BFS, DFS and reverse postorder — the standard orders for walking a program's statements, and why reverse postorder hands every statement its input complete.
  2. Fixpoints and worklists — how an analysis handles loops: apply the rules until nothing changes, and why the visiting order matters for cost but not for the answer.
  3. Gen/kill and reaching definitions — for every read, which writes could have produced the value it sees, and why only a certain overwrite may discard one.
  4. Byte-extent aliasing — fields as byte ranges: how groups, REDEFINES and partial writes alias, and why overlapping is not the same as covering.
  5. Value sets and dynamic calls — resolving CALL WS-PGM statically by tracking the values a field can hold, and the reasons that set may be incomplete.

Related — not part of cobble's own build-up, each pulled from wherever it actually came from:

  • Dominance and reachability — used by a different tool in the forge; where a branch's arms come back together, exactly which statements are inside a loop, and why carrying one pointer per statement instead of a whole candidate set turns an impractically slow computation into a fast one.
  • Tree zippers — a data structure, not an analysis, from cobol-rekt's catalogue; a cursor into an immutable tree that remembers the way back up, so editing one node deep inside only rebuilds the handful of ancestors above it.
  • Reducibility and loop detection — also from cobol-rekt's catalogue; three ways to tell a loop with one entry from a loop with two, agreeing on the same tiny counter-example each time.
  • Reaching conditions — also from cobol-rekt's catalogue; not to be confused with reaching definitions above — this is the boolean condition on the data that must hold to reach a statement at all, not which write a read sees.
  • Eliminating GOTOs — also from cobol-rekt's catalogue; a forward jump becomes an IF, a backward jump becomes a loop, and a jump into an outer scope climbs there one level at a time.
