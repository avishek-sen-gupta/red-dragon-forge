Conversational CICS

Cooperative Suspend / Resume as a core VM primitive

Running unmodified conversational COBOL/CICS (one task that loops SEND → RECEIVE) on RedDragon's VM — by promoting one scalar into the resumable state, not by rewriting the interpreter.

   pseudo-conversational (today)        conversational (goal)
   ──────────────────────────────       ─────────────────────────────────
   SEND MAP                             PERFORM UNTIL done
   RETURN TRANSID  ── task ends         ┌  SEND MAP
   (state in COMMAREA, rebuilt)         │  RECEIVE MAP   ◄── BLOCKS, task stays alive
                                        │  ...process... (working-storage persists)
   one run_cics() = one turn            └  END-PERFORM
                                        RETURN          ── one run_cics() = whole convo

Benchmark: Nantero1/zBANK — 140 lines, one PERFORM UNTIL over 3 screens, single terminal RETURN.

the execution model today

A flat PC-driven dispatch loop

run_cics() ──► execute_cfg(vm, entry)
                 │
                 ▼
   ┌────────────────────────────────────────────────────┐
   │  for step in range(max_steps):     ◄── SAFETY BUDGET│   (not graph traversal)
   │      block = cfg.blocks[current_label]   ← dict lookup by label
   │      inst  = block.instructions[ip]                 │
   │      update = handler(inst, vm, ctx)   ← PURE: returns a StateUpdate
   │      apply_update(vm, update)                        │
   │      ── advance the program counter ──              │
   │         ip += 1                      (sequential)    │
   │         current_label = successors[0] (fall-through) │
   │         current_label = update.next_label (branch)   │
   └────────────────────────────────────────────────────┘
        cursor = (current_label, ip)   ◄── LOOP-LOCAL scalars
        vm     = VMState               ◄── everything else, as DATA

Not a linked-list walk, not recursion. A classic fetch–decode–execute loop; the for only bounds total instructions.

Loop-local — control cursor ✗

current_label
ip

The only control state not promoted to data. It stayed in the loop because run-to-completion only ever moves it forward and discards it at exit.

Continuation targets are data (next_label, continuation table). The position never had to be — until now.

Conversational suspend is the first feature that needs the cursor to be data too.

the primitive

Reify the cursor → ExecutionState

   ExecutionState = ( VMState , current_label , ip )      ← a complete, serializable task

   1.  New result kind         Suspend(payload)        ← handlers stay PURE; the LOOP interprets it
                                                          (just like next_label / continuation_writes)

   2.  Loop, on Suspend:       stop; return (ExecutionState, payload)   ── instead of running to RETURN

   3.  Public entry:           resume(execution_state, injected_value)
                                  └─ re-enter the SAME loop seeded with saved (current_label, ip)
                                     deliver injected_value into a register at the suspend site

Generic / frontend-agnostic

A cooperative "yield a value / resume with a value" primitive. Reusable by a REPL, a single-stepping debugger, a lazy generator in any language. CICS-unaware.

CICS RECEIVE is just one user

RECEIVE lowers to SEND payload + SUSPEND; the dispatcher's resume injects the terminal input. Honors "one mechanism for all frontends."

the round-trip

Suspend / resume, one logical level

   DRIVER (dispatcher / test / live terminal)        VM  (execute_cfg + resume)
   ──────────────────────────────────────────       ──────────────────────────────
        screen ◄───────────────────────────────  SEND MAP → Suspend(screen)
        │                                              (ExecutionState frozen: vm + PC)
   inspect / render
        │
   next input ─────────────────────────────────► resume(ExecState, input)
                                                       RECEIVE returns input
                                                       ...process; working-storage intact...
        screen ◄───────────────────────────────  SEND MAP → Suspend(screen)
        │                                              ⟳ loop iteration N+1
        ⋮                                              ⋮
   (user quits)
        done   ◄───────────────────────────────  RETURN  → DispatchResult(RETURN)

Deterministic: switches are explicit and ordered — no threads, no timeout=, no races. Working-storage persists because it's one ExecutionState across the whole conversation.

state restoration · the crux

Two stacking mechanisms — capture both

   ┌───────────────────────── TASK (the suspendable / serializable unit) ─────────────────────────┐
   │                                                                                              │
   │   CICS logical-level stack          dispatcher-owned          (only for EXEC CICS LINK)      │
   │   ───────────────────────                                                                    │
   │     ┌───────────────────────────────────────────────┐                                        │
   │     │ level 0: PROG A   ExecutionState  @ LINK B  ───┼─ frozen at its call site               │
   │     ├───────────────────────────────────────────────┤                                        │
   │     │ level 1: PROG B   ExecutionState  @ RECEIVE ◄──┼─ SUSPEND here (leaf)                   │
   │     │            └ VMState.call_stack:  [perform, CALL'X' ...]  ← COBOL nesting, IN VMState   │
   │     └───────────────────────────────────────────────┘                                        │
   │                                                                                              │
   └──────────────────────────────────────────────────────────────────────────────────────────────┘
     resume leaf ─► B RETURNs ─► pop to A, hand back COMMAREA ─► resume A after LINK ─► ... ─► done

Two tiers, both plain data: the dispatcher holds the CICS logical-level stack of ExecutionStates; each VMState holds its own COBOL call_stack. Inject terminal input at the leaf, a callee COMMAREA at an interior level on its RETURN.

"called by another program" — three cases

Each restores differently

mechanismwhere the stack livesrestoration
COBOL CALL / PERFORM vm.call_stack (inside VMState) FREE one snapshot captures the whole tower; proven by CardDemo's CALL/RETURN
CICS XCTL (transfer, no return) — (parent discarded) NOTHING task is the target; no parent to restore
CICS LINK (call w/ return) dispatcher logical-level stack THE WORK stack of ExecutionStates; not modeled yet (no DispatchKind.LINK)

Key reassurance: you don't invent restoration — call_stack already does correct save/restore on every RETURN. Suspension just freezes that same structure mid-flight.

If CALL/RETURN is correct, suspend/resume across calls is correct by the same mechanism.

two gotchas the snapshot doesn't cover

Aliasing & held resources

① COMMAREA / region aliasing

A callee's linkage COMMAREA may alias the caller's working-storage region. Merge levels into one VMState and a naïve deep-copy splits the alias into two buffers → writes stop propagating.

Fix: keep one VMState per LINK level; marshal COMMAREA (copy-in / copy-out) at the boundary — which is CICS semantics. Sidesteps aliasing entirely.

② Resources held across the wait

zBANK does READ … UPDATE (a record lock) and holds it across RECEIVE. Locks live in the VsamEngine — outside every VMState.

Fix: key lock ownership to the Task, not to an execute_cfg invocation. Survives suspend/resume; releases on the task's final RETURN/abend. (Same for the max_steps budget.)

Tactical spike → strategic primitive

   LATER ── if conversational graduates to first-class ───────────────────────────

in one breath

The whole idea

RedDragon is already 90% resumable: the call stack, continuations, registers, heap and working-storage are all plain, deep-copyable data in VMState.

The only thing not promoted to data is the loop's cursor (current_label, ip). Promote it into an ExecutionState, add a generic Suspend result + a resume() entry, and the VM gains cooperative suspend/resume — without threads, coroutines, or rewriting the loop.

Restoration then layers cleanly: COBOL nesting rides inside one VMState (free); CICS LINK nesting becomes a dispatcher stack of ExecutionStates; XCTL needs nothing. Resources & budget are task-scoped, not invocation-scoped.

Conversational RECEIVE = SEND + SUSPEND. Same primitive a REPL, a debugger, or a generator would use.
