What is Cicada?

Real, unmodified COBOL
↓

preprocess · lower · dispatch · VSAM · BMS
↓
RedDragon VM
  • Dispatch Pseudo-conversational transaction routing — programs run one turn at a time, suspending between terminal interactions
  • VSAM In-memory KSDS engine — READ, WRITE, REWRITE, DELETE, browse (STARTBR/READNEXT/READPREV)

Preprocessor — inject_dfheiblk

Making EIB fields visible before the parser runs

Before
WORKING-STORAGE SECTION.
01 WS-MY-FIELD PIC X(10).
…
→
After
WORKING-STORAGE SECTION.
COPY DFHEIBLK. ← injected
01 WS-MY-FIELD PIC X(10).
…
Why: Every CICS program reads EIB fields — EIBAID (attention key), EIBCALEN (commarea length), EIBTRNID (current transid). Without COPY DFHEIBLK these names are undefined; the parser would reject them. Cicada injects the COPY before parsing begins rather than requiring it in every source file.
Implementation: cics/preprocessor.py · apply_cics_prepass()

Preprocessor — DFHRESP pre-pass

Resolving condition names before the IR is built

Stage 1 — Text pass

Scans the source text for DFHRESP(condition) patterns and replaces each condition name with its numeric EIBRESP code.

ConditionCode
NORMAL0
ERROR1
NOTFND13
DUPREC14
ENDFILE20
DISABLED84
unknown9999
Stage 2 — AST pass

Walks the parsed expression tree and replaces every {kind:dfhresp} node with the resolved numeric literal — so the IR sees a plain integer, not a symbolic name.

Why two stages? The main parser would reject bare condition names in IF expressions. The text pass normalises them first; the AST pass catches any stragglers the grammar already absorbed.
Implementation: cics/dfhresp_prepass.py · resolve_dfhresp_nodes()

RESP writeback

When an EXEC CICS verb includes a RESP(data-name) clause, a second IR instruction writes the builtin's return value back to that data item — a side-channel separate from the normal return path.

NOHANDLE / RESP2

If RESP is present (or NOHANDLE is set), condition handling is suppressed — the program inspects EIBRESP itself rather than relying on the default error handler.

VSAM — file table & VsamEngine

CICS files resolved through the CSD to catnip's system catalog

File table

Each CSD DEFINE FILE(name) DSNAME(dsn) maps a CICS file to a DSN. The DSN is looked up in catnip's system catalog, in the directory the region TOML's system names — the same catalog jackal's batch jobs use.

Catalog entryThe CICS file reads
KSDSthe cluster, by its primary key
Pathits base cluster, by the alternate index's key
anything else, or not catalogednothing: the region stops at startup, naming the file and the DSN
Record length and key come from the catalog label, not the region config. Implementation: cics/vsam/file_table.py · cics_files
VsamEngine (thin CICS adapter)

Owns no storage. The catalog's own dataset file is the store, served by RedDragon's shared file-resident access-method drivers — the same ones COBOL batch & IDCAMS use. The adapter opens the dataset per operation, picks the driver by its label, and maps the result to EIBRESP.

Driver routing (by the dataset's label)
KSDS → open_driver(INDEXED) — binary search over a key-sorted file
Path → AlternateIndexDriver over the base cluster — alternate-key order, duplicates in primary-key order; DUPKEY (15) when more follow; writes change the base cluster

CardDemo's CXACAIX is the path over CCXREF's cluster: a write through one is read through the other.
CardDemo data: installed once with uv run catnip install config/carddemo/data.toml --system DIR from config/carddemo/data.toml.

Browse keeps one open driver instance per (task, file, cursor_id). READNEXT→READPREV reversal is handled by the driver's own cursor (read_seq/read_prev) — no separate direction bookkeeping in the adapter.
The store: a backing flat file
No in-memory copy, no backends
Each dataset's <system>/datasets/<DSN> file is the store. RedDragon's file-resident drivers read/write it directly — so cicada, COBOL batch, and IDCAMS share one storage implementation and one set of bytes. A region's writes survive a restart.
Loading — catnip install
Validates a data declaration whole, then copies the seeds in. Each KSDS is written key-sorted (the binary-search driver requires it); alternate indexes and paths are catalog entries with no bytes of their own.
EIBRESP comes from mapping the drivers' neutral AccessCondition (cics/vsam/eibresp.py). A file not in the table returns DISABLED.

Dispatcher — DispatchResult

What exits each program execution

Kind Meaning Carries
RETURN Task ends normally. No successor. —
RETURN_TRANSID Pseudo-conversational suspend. A new terminal interaction starts the next turn on a (possibly different) transid. transid, commarea
XCTL Transfer control to a named program. Same transid, same task — no terminal round-trip. program, commarea
ABEND Abnormal termination. Task ends. abcode (TRNI, PGMI, …)

Dispatcher — _advance_routing

Single source of truth for "what runs next"

RETURN_TRANSID
Look up result.transid in the CSD-derived transid_to_program map.
✔ found → continue: new transid + new program + commarea
✘ unknown transid → ABEND TRNI
XCTL
Look up result.program in the compiled program_cache.
✔ found → continue: same transid + new program + commarea
✘ unknown program → not reached: the XCTL raised PGMIDERR in the program
RETURN  /  ABEND
Pass through unchanged → terminal state. Caller receives the original DispatchResult.
Key design: both CicsRegion and the blocking dispatcher loop call _advance_routing. There is one routing rule, not two. Tests can exercise it independently.
Implementation: cics/dispatcher.py · _advance_routing()

Pseudo-conversational turns

CardDemo sign-on flow — one task, many programs

Turn 1
CC00
transid CC00 → program COSGN00C
SEND MAP (login screen displayed) → RETURN TRANSID CC00
commarea: empty (first turn)
↓   user types credentials + presses ENTER   ↓
Turn 2
CC00
transid CC00 → program COSGN00C
RECEIVE MAP → validate credentials → XCTL COMEN01C (no terminal round-trip)
↓   immediate — XCTL switches program within same task   ↓
Turn 2′
CC00
transid CC00 (carried) → program COMEN01C
SEND MAP (main menu) → RETURN TRANSID CC00
commarea: session state (user ID, etc.)
↓   user selects option   ↓   …
The pattern: commarea is the task's working memory; transid is its "return address". Programs are stateless between turns — the region holds all mutable state.

CardDemo — CSD walkthrough

How transid → program mappings are built

parse_csd() reads the CSD file and produces the transid_to_program dict that _advance_routing consults on every RETURN_TRANSID.

TransidProgramFlow
CC00COSGN00CSign-on
CA00COMEN01CMain menu
ACNTCOACTUPCAccount update
TRANCOTRN00CTransaction list
BLLPCOBIL00CBill payment
CSD grammar (structural, not regex)
DEFINE TRANSACTION(CC00)
    PROGRAM(COSGN00C)
    GROUP(CARDDEMO)

DEFINE TRANSACTION(ACNT)
    PROGRAM(COACTUPC)
    GROUP(CARDDEMO)
Attributes are order-independent. parse_csd() uses a Lark grammar — not fragile regex — so DEFINE blocks can span continuation lines.

Key invariants

1
No edits to the RedDragon VM core.
Every CICS behaviour reaches the VM via CallFunction IR to registered builtins — the same extension point any language frontend uses. The files vm/**, ir.py, run.py, executor.py, cfg.py are untouched.
2
CicsLoweringStrategy is injection, not inheritance.
It is passed into CobolFrontend at construction — the standard extension point. Swapping it for a different strategy (e.g. a mock or a no-op) requires no subclassing and leaves the frontend unchanged.
3
_advance_routing is the single source of truth for routing.
Both CicsRegion and the blocking dispatcher loop call it. There is one routing rule — not two implementations that could diverge. It can be tested in isolation without a running VM.
4
VsamEngine is a thin adapter over the shared storage engine.
Record I/O delegates to RedDragon's file-resident access-method drivers (the same ones COBOL batch & IDCAMS use); the system catalog's dataset file is the store. The adapter holds only CICS state — the file table, held key, task cursors — and the neutral-condition→EIBRESP mapping.
