# Forge Runner — Build a Package Once, Run It From env.toml — Design

**Date:** 2026-10-15
**Issue:** red-dragon-forge-jr5 (follows red-dragon-forge-96h, programs carry their declarations in their IR)

## Problem

Every run of a COBOL application re-parses, re-lowers and re-links its programs. jackal compiles
each step's program from source at run time; cicada's region compiles every program when it
starts; squall's CLI compiles its one program. There is no compiled artefact to keep, ship or
run twice, and each runtime has its own configuration for where sources, copybooks, maps and
datasets come from.

## Goal

One build command turns a `build.toml` into `<name>.zip`, a package of linked programs. One run
command runs a package as `env.toml` describes: a program on its own, a JCL job, or a CICS region
served over TN3270. Runs never parse, lower or link. Scope is parity with what each runtime does
today.

## Decisions

**D1. Tool paths are environment variables.** `bridge-env.sh` also exports `HLASM_EXPORT`. The
build command reads `PROLEAP_BRIDGE_JAR` and `HLASM_EXPORT`, and stops naming any one that is
unset.

**D2. `build.toml` is the application's build descriptor.**

```toml
[paths]
source_dirs = ["app/cbl"]
copybook_dirs = ["app/cpy"]
copybook_exts = ["cpy", "CPY"]

[build]
name = "carddemo"
programs = ["COSGN00C", "CBACT01C"]
coprocessors = ["cics", "sql"]      # any of: sql, cics, cics-conversational; [] for none
tolerant = false
out_dir = "out"

[cics]                              # required when coprocessors include cics
bms_dirs = ["app/bms"]
csd_files = ["app/csd/CARDDEMO.CSD"]
```

Each listed program is the main program of its own run unit: the programs it CALLs are found
in `source_dirs` and linked in; LINK and XCTL targets are run units of their own and must be
listed. A program name is its member name (the CICS load-module name). The coprocessor specs are
built with empty runtime state. jackal's LE stubs are always on the search path, so every
program can run under any mode.

**D3. `litter` is a new workspace member holding the package.** It imports no runtime; the
forge root and jackal and cicada import it. It provides:

- `build(programs, specs, search_dirs, work_dir, transactions, maps) -> Path` — compiles each
  program with red-dragon's `compile_program` and the given `CoprocessorSpec`s, and writes the
  zip. red-dragon's intermediate files go in `work_dir` (`out_dir/work/`), and a rebuild reuses
  them; red-dragon's one change is `compile_program` gaining `work_dir`. `transactions` is a
  tuple of frozen `Transaction(transid, program)`; `maps` is the path of the map catalog file
  the BMS compile wrote (absent for a package without cics), copied in unchanged.
- `open(path) -> Package` — the typed manifest (programs, coprocessor names, transactions),
  each program's `LinkedProgram` read with `LinkedCodec.read`, and the map catalog's bytes for
  cicada to read with its own reader.

**D4. The package is `<name>.zip`**, like a JAR:

| entry | content |
|---|---|
| `manifest.json` | program name → linked file; coprocessor names; the transaction table from the CSD |
| `maps.json` | the map catalog the BMS compile produced |
| `programs/<PROGRAM>.linked.json` | red-dragon's linked file, copied unchanged |

The forge never serialises a `LinkedProgram` itself. A package whose manifest names a missing
linked file, or whose linked file fails `LinkedCodec.read`, stops the run naming the entry.

**D5. The build command** (forge root) reads `build.toml`; builds squall's and cicada's
coprocessor specs from `coprocessors`; compiles the BMS maps once with `hlasm_export` into
symbolic copybooks (on the copybook path for the compile) and the map catalog (into
`maps.json`); reads the CSD files into the transaction table; and calls `litter.build`. The
transaction table always comes from CSD files, shipped or generated by `cobble-csd`, never a
hand-written table.

**D6. `env.toml` is the place a package runs.**

```toml
package = "out/carddemo.zip"

[paths]
system = "region/system"            # catnip's system directory

[sql]                               # required when the package was built with sql
                                    # DSN from SQUALL_DB2_DSN

# exactly one of [plain], [jcl], [cics]

[plain]
program = "CBACT01C"
max_steps = 1000000

[plain.files]
ACCTFILE = "AWS.M2.CARDDEMO.ACCTDATA.PS"

[jcl]
job = "jcl/READACCT.jcl"
proclib_dirs = ["jcl/proclib"]

[cics]
initial_transid = "CC00"
host = "127.0.0.1"
port = 3270
```

The section present picks the mode; there is no mode key. A file with none or more than one of
`[plain]`, `[jcl]`, `[cics]` stops the run naming what it found. A missing `[sql]` when the
manifest names sql, a missing `[cics]` program or transid, or a program the manifest does not
hold stops the run naming it.

**D7. `[plain]` runs one program directly.** Its files are named by catalog name:
`[plain.files]` maps each ASSIGN name to a dataset in catnip's catalog, which supplies the
record format, length and record layout, as a DD with `DSN=...,DISP=SHR` does. No file is described in
`env.toml`. The program runs as jackal runs a one-step program — the same allocation,
file-status and return-code behaviour — with the step's DDs built from `[plain.files]`.

**D8. `[jcl]` runs a job with jackal against the package.** jackal runs packages only: a
`JobRunner` takes a `litter.Package` in place of a source directory and a compiler, and a step's
`EXEC PGM=X` (or `DSN RUN PROGRAM(X)`) takes `X` from the package. A program the package does
not hold is a missing program, handled by jackal's existing missing-program strategy. Datasets
come from the job's DDs and catnip's catalog. The step budget and the unresolved-reference,
missing-data and missing-program strategies are jackal CLI's current defaults. jackal's tests
build their fixtures with `litter.build`; `ProgramCompiler`, `ProgramSources` and the `--source-dir`,
`--copybook-dir` and `--link` options go.

**D9. `[cics]` serves a region assembled from the package over TN3270.** cicada's
`build_region` splits into compile (now `litter.build`'s job) and assemble (programs, maps,
transaction table and files into a region), and the run command assembles from the package.
CICS datasets come from the CSD's `DEFINE FILE` → `DSNAME`, resolved through catnip.
`min_commarea_len` leaves configuration: it defaults to 32763, CICS's maximum COMMAREA length
(IBM, "Maximum length for the COMMAREA"; a longer COMMAREA raises LENGERR), and a bead records
replacing the padding with the caller's real storage.

## Out of scope

- Migrating CardDemo onto `build.toml` and `env.toml`, and retiring `cicada-tn3270`,
  `carddemo-db2-cli` and the aggregate region TOMLs — the follow-up.
- Any runtime behaviour not present today.

## Testing

- **litter:** a built package opens to the same `LinkedProgram`s the compile produced (codec
  round trip), with the manifest and maps as given; a rebuild with an unchanged work directory
  reuses red-dragon's intermediate files; a missing or unreadable linked file stops `open`
  naming the entry.
- **build command:** a `build.toml` with a CICS program, a batch program and a CSD yields a
  package whose manifest lists both programs, the coprocessors and the CSD's transactions; an
  unset `PROLEAP_BRIDGE_JAR` or `HLASM_EXPORT` stops the build naming it.
- **run command:** each of the D6 configuration errors stops with its message; `[plain]` runs
  a program reading and writing cataloged datasets with the same output and return code as a
  one-step job; `[jcl]` runs a multi-step job from a package with the results jackal produces
  today; `[cics]` serves the sign-on screen of a region assembled from a package.
- **jackal and cicada:** their suites, including the CardDemo end-to-end and Db2 tests, pass
  running packages.

## Units

1. **red-dragon:** `compile_program` gains `work_dir`. Push; bump the forge.
2. **litter:** the member, `build` and `open`, `bridge-env.sh` exporting `HLASM_EXPORT`.
3. **jackal:** runs packages only (D8); its tests build fixtures with `litter`.
4. **cicada:** `build_region` splits into compile and assemble; assemble from a package (D9).
5. **forge root:** the build command (D2, D5) and the run command (D6–D9).
