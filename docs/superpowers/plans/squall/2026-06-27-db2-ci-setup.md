# squall DB2 Test Infrastructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tracked, reproducible DB2 stack (official image, no committed credentials) that makes squall's full suite — including the live-Db2 tests — run green locally and (later) in CI.

**Architecture:** A committed `docker-compose.yml` on the official anonymously-pullable `icr.io/db2_community/db2` (privileged, healthchecked) + a `/var/custom` init that creates MOJO/MOJO2 + a `db2/dsn-env.sh` that constructs the DSNs from a gitignored `.env` (password never committed) + Makefile targets. Phase 1 is built, **validated against a real DB2**, then committed; Phase 2 (GitHub Actions) is authored only after Phase 1 is proven green.

**Tech Stack:** Docker Compose v2 (`docker compose`), IBM DB2 community image `icr.io/db2_community/db2:11.5.9.0`, GNU Make, GitHub Actions (Phase 2), pytest.

## Global Constraints
- **No committed credentials.** The DB2 password lives ONLY in a gitignored `.env` (local) or a GH secret (CI). Committed files contain placeholders + the DSN *shape* only. `.gitignore` already has `.env` / `.env.*` / `!.env.example`.
- **Official image, pinned:** `icr.io/db2_community/db2:11.5.9.0` (verified anonymously pullable). Not `:latest`. No `anilmahadev/*` at test-run time.
- **`privileged: true`** is mandatory for DB2 community.
- **Tests self-provision schema** (CREATE/DROP their own tables) — do NOT seed tables. Real DB2 only needs databases **MOJO + MOJO2**; "SAMPLE" is a logical connection name, not a DB.
- **DSN env var names (exact):** `SQUALL_DB2_DSN`, `SQUALL_DB2_DSN2`; format `DATABASE=<db>;HOSTNAME=<host>;PORT=<port>;PROTOCOL=TCPIP;UID=db2inst1;PWD=<password>`. Plus `PROLEAP_BRIDGE_JAR`.
- **Fail loud:** `dsn-env.sh` asserts `DB2_PASSWORD` + `PROLEAP_BRIDGE_JAR` are set (no silent default password). Healthcheck-wait fails on timeout rather than running tests against a not-ready DB2.
- **Do not disturb the existing `db2server` container.** Validate the new stack on a **different host port** (`DB2_PORT=15000`) so the two coexist during validation.
- **SEQUENCING GATE:** Phase 1 (Tasks 1–5) must be validated green (Task 5) and committed before Phase 2 (Task 6, CI) is authored/committed. Per the user: no pipeline changes pushed to GitHub until local is proven.
- Makefile conventions: `PYTEST = uv run --no-sync python -m pytest`, `PYTEST_PATHS ?= tests/`, `PROLEAP_BRIDGE_JAR ?= $(CURDIR)/vendor/red-dragon/proleap-bridge/target/proleap-bridge-0.1.0-shaded.jar`, `.PHONY` list at line 18.

## Task 1: `/var/custom` init script — create MOJO + MOJO2

**Files:** Create `db2/custom-init/01-create-databases.sh`.

**Interfaces:** Runs inside the container as the IBM image's post-init hook (mounted to `/var/custom`). Executes as root; uses `su - db2inst1 -c "..."`. Idempotent.

- [ ] **Step 1: Write the script.** `db2/custom-init/01-create-databases.sh`:
```bash
#!/bin/bash
# IBM db2_community image runs scripts in /var/custom once, after instance setup.
# DBNAME=MOJO already created the first database; create MOJO2 here if absent.
# Tests self-provision their own tables, so no schema seeding.
set -euo pipefail

create_db_if_absent() {
  local db="$1"
  if su - db2inst1 -c "db2 list db directory" | grep -q "Database alias *= ${db}$"; then
    echo "custom-init: ${db} already exists, skipping"
  else
    echo "custom-init: creating ${db}"
    su - db2inst1 -c "db2 create database ${db}"
  fi
}

su - db2inst1 -c "db2start" || true   # ensure the manager is up before CREATE
create_db_if_absent MOJO
create_db_if_absent MOJO2
echo "custom-init: databases ready"
```
- [ ] **Step 2: Make it executable.** `chmod +x db2/custom-init/01-create-databases.sh`.
- [ ] **Step 3: Commit.**
```bash
git add db2/custom-init/01-create-databases.sh
git commit -m "feat(db2): /var/custom init creating MOJO + MOJO2 (idempotent)"
```
(Real verification of this script happens in Task 5 — it only runs inside a live container. No standalone test here; it is shell glue exercised end-to-end by the validation task.)

## Task 2: `docker-compose.yml` — the DB2 service

**Files:** Create `docker-compose.yml`.

**Interfaces:** Service `db2`; consumes `${DB2_PASSWORD}` and `${DB2_PORT:-50000}` from the environment; exposes DB2 on the host port; healthcheck signals readiness.

- [ ] **Step 1: Write `docker-compose.yml`:**
```yaml
services:
  db2:
    image: icr.io/db2_community/db2:11.5.9.0
    container_name: squall-db2
    privileged: true
    ports:
      - "${DB2_PORT:-50000}:50000"
    environment:
      LICENSE: accept
      DB2INSTANCE: db2inst1
      DB2INST1_PASSWORD: ${DB2_PASSWORD:?DB2_PASSWORD must be set (see .env.example)}
      DBNAME: MOJO
    volumes:
      - ./db2/custom-init:/var/custom:ro
      - squall_db2_data:/database
    healthcheck:
      # Ready only when MOJO2 (created last by the init hook) is connectable.
      test: ["CMD-SHELL", "su - db2inst1 -c 'db2 connect to MOJO2' >/dev/null 2>&1"]
      interval: 15s
      timeout: 10s
      retries: 40
      start_period: 60s

volumes:
  squall_db2_data:
```
- [ ] **Step 2: Validate compose syntax.** `docker compose config -q` (with `DB2_PASSWORD=x` exported) → no error. (Full stand-up is Task 5.)
- [ ] **Step 3: Commit.**
```bash
git add docker-compose.yml
git commit -m "feat(db2): docker-compose on official icr.io db2 (privileged, healthchecked)"
```

## Task 3: Credentials — `.env.example` + `db2/dsn-env.sh` (no committed secret)

**Files:** Create `.env.example`, `db2/dsn-env.sh`.

**Interfaces:** `db2/dsn-env.sh` is `source`d by the Makefile/CI; it reads `.env`, asserts required vars, and exports `SQUALL_DB2_DSN`, `SQUALL_DB2_DSN2`.

- [ ] **Step 1: Write `.env.example` (committed — placeholders only):**
```bash
# Copy to .env (gitignored) and set a password. NEVER commit .env.
# Self-chosen throwaway DB2 password for local/CI test DB2.
DB2_PASSWORD=changeme
# Host port the compose DB2 publishes (default 50000; use 15000 to avoid
# colliding with a pre-existing local db2 container during validation).
DB2_PORT=50000
# Host the DSNs connect to (localhost for local compose).
DB2_HOST=localhost
```
- [ ] **Step 2: Write `db2/dsn-env.sh` (committed — constructs DSNs, no secret):**
```bash
#!/bin/bash
# Source this to export SQUALL_DB2_DSN / SQUALL_DB2_DSN2 for the test suite.
# The password comes from .env (gitignored) or the environment (CI secret) —
# it is NEVER committed; only the DSN shape lives here.
set -euo pipefail

_here="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
if [ -f "${_here}/.env" ]; then
  set -a; . "${_here}/.env"; set +a
fi

: "${DB2_PASSWORD:?DB2_PASSWORD not set (copy .env.example to .env, or set it in CI)}"
: "${PROLEAP_BRIDGE_JAR:?PROLEAP_BRIDGE_JAR not set (the ProLeap bridge JAR path)}"
_host="${DB2_HOST:-localhost}"
_port="${DB2_PORT:-50000}"

_dsn() { echo "DATABASE=$1;HOSTNAME=${_host};PORT=${_port};PROTOCOL=TCPIP;UID=db2inst1;PWD=${DB2_PASSWORD}"; }
export SQUALL_DB2_DSN="$(_dsn MOJO)"
export SQUALL_DB2_DSN2="$(_dsn MOJO2)"
```
- [ ] **Step 3: Make executable + confirm `.env` is gitignored.** `chmod +x db2/dsn-env.sh`; `git check-ignore .env` (after a dummy `.env`) → ignored. Confirm `git status` does NOT show `.env`.
- [ ] **Step 4: Commit.**
```bash
git add .env.example db2/dsn-env.sh
git commit -m "feat(db2): .env.example + dsn-env.sh — DSNs constructed from a non-committed password"
```

## Task 4: Makefile targets

**Files:** Modify `Makefile`.

**Interfaces:** Adds `db2-up`, `db2-down`, `db2-clean`; `test` sources `db2/dsn-env.sh`. Consumes `db2/dsn-env.sh` (Task 3), `docker-compose.yml` (Task 2).

- [ ] **Step 1: Add targets + extend `test`.** In `Makefile`, add to `.PHONY` (`db2-up db2-down db2-clean`) and add:
```makefile
db2-up:
	docker compose up -d db2
	@echo "Waiting for DB2 healthy (first init can take several minutes)..."
	@until [ "$$(docker inspect -f '{{.State.Health.Status}}' squall-db2 2>/dev/null)" = "healthy" ]; do \
	  sleep 5; \
	  [ "$$(docker inspect -f '{{.State.Health.Status}}' squall-db2 2>/dev/null)" = "unhealthy" ] && { echo "DB2 unhealthy"; exit 1; }; \
	done
	@echo "DB2 healthy."

db2-down:
	docker compose down

db2-clean:
	docker compose down -v
```
  Change `test` to source the DSN env (keep its `jar` dep):
```makefile
test: jar
	. db2/dsn-env.sh && $(PYTEST) $(PYTEST_PATHS) $(PYTEST_ARGS)
```
  (Document in the Makefile header comment that `make db2-up` must precede `make test`.)
- [ ] **Step 2: Verify the targets parse.** `make -n db2-up db2-down db2-clean` (dry-run) → prints the recipes, no make error.

- [ ] **Step 1: Write `.github/workflows/ci.yml`:**
```yaml

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { submodules: recursive }
      - uses: astral-sh/setup-uv@v5

          PROLEAP_BRIDGE_JAR: ${{ github.workspace }}/vendor/red-dragon/proleap-bridge/target/proleap-bridge-0.1.0-shaded.jar
```
